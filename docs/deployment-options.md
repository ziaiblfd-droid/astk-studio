# 发布与计算部署方案

ASTK Studio 分为公开静态站点和可选计算服务两部分。

## 推荐方案

### GitHub Pages

面向所有研究者公开，提供论文数据浏览、七类事件演示、工作流预览、输入模板和 Docker 文档。

GitHub Pages 不接收或保存用户数据，也不执行 ASTK。页面检测不到 `/api/health` 时会自动进入静态演示模式。

### GitHub 仓库与 Docker

研究者克隆仓库后在自己的 Linux 服务器运行：

```bash
docker compose up --build -d
```

本地站点检测到任务 API 后，会启用文件上传、ASTK 计算、结果解析与 ZIP 下载。

## 校内服务器

校内服务器可以作为组内计算节点，但只有在满足以下条件后才能作为公共网站后端：

- 具有校外可访问的公网入口
- 防火墙允许 HTTPS 访问
- 配置域名、TLS 证书和反向代理
- 学校允许对外提供计算服务
- 有用户配额、数据清理和安全审计机制

若服务器只能通过校园网或 VPN 访问，它不适合作为面向外部研究者的在线计算后端。

## 未来公共计算

获得公网 Linux 主机后，可以部署同一 Docker 镜像。公共服务还应增加 HTTPS、身份验证或匿名配额、定时删除数据、资源限制、恶意文件扫描与日志审计。

不建议使用 GitHub Actions 接收任意研究者数据并执行 ASTK。Actions 适合构建和发布站点，不适合作为公开计算队列。
